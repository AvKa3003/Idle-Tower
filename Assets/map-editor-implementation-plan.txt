Map Editor — план реализации
============================
Дата: 2026-10-17
Статус: план (код не начат)

Цель
----
Editor Window для визуального редактирования MapConfig (iso-превью как в игре).
Source of truth — ScriptableObject MapConfig.
Прогресс клетки в сейве привязан к стабильному instance id (не к координате).
Совместимость со старыми сейвами (до id) НЕ нужна — игра не в продакшене.
Пункт на будущее: когда появятся миграции сейва — адаптировать их под instance id клетки.


Общие правила продукта
----------------------
1. Сохранение MapConfig только по явной кнопке Save в окне редактора
   (не автосейв на каждый клик; Undo внутри сессии — по желанию этапа UI).
2. Dirty-флаг (без глубокого скана/диффа ассета):
   любое изменение в сессии редактора (paint, erase, move, правки в Inspector,
   авто-генерация instanceId и т.п.) → dirty = true.
   После успешного Save или Discard при смене карты → dirty = false.
   На кнопке Save — индикатор несохранённых изменений (достаточно зелёной
   точки / маркера на иконке или рядом с кнопкой). Без dirty маркер скрыт
   или нейтральный вид кнопки.
3. При смене карты (drop другого MapConfig / очистка):
   если dirty → диалог «Сохранить изменения?» Да / Нет / Отмена
   - Да: Save, затем переключить
   - Нет: отбросить правки в памяти, переключить
   - Отмена: остаться на текущей карте
4. Превью: виртуализация только «вне видимой области не создавать/не обновлять
   визуал»; чанки ассета / стриминг диска — не делать.
5. Свойства клетки — в правом Inspector Unity (Custom Editor MapConfig
   показывает выбранную entry), не свой полный UI для Site/Raid.
6. Добавление клеток: drag MapCellDefinition из Project на клетку / paint.
7. Move: меняет Coord, instanceId не меняется.


Модель данных (итог)
--------------------
MapConfigEntry:
  - string instanceId   // GUID, задаётся при создании entry в редакторе
  - Vector2Int Coord
  - MapCellDefinition Cell
  - MapCellSiteConfig Site

MapCellSave (сейв игрока):
  - string instanceId   // ключ прогресса
  - int x, y            // дублировать позицию на момент сейва (удобство/отладка)
  - остальное как сейчас (behaviorType, behaviorStateJson, …)

MapState / MapSystem Load:
  - строить runtime из MapConfig по Coord как сейчас для геймплея сетки;
  - накладывать прогресс из сейва по instanceId → entry/runtime.

MapCellDefinition.id — по-прежнему id ШАБЛОНА (camp/forest), не путать
с instanceId экземпляра на карте.


Как давать задачи ИИ
--------------------
Ниже этапы — отдельные запросы «сделай этап N» по порядку.
Можно попросить «этапы 1–2 за раз», если контекст свежий.
Не рекомендуется «всё за один запрос»: затронуты данные сейва, рантайм карты
и Editor UI — лучше резать по границам ниже.

Зависимости: 1 → 2 → 3 → 4 → 5 (5 опирается на 3–4).


════════════════════════════════════════════════════════════════════════
ЭТАП 1 — Instance id в данных + сейв/рантайм (без Editor Window)
════════════════════════════════════════════════════════════════════════
Запрос ИИ (пример):
  «Реализуй этап 1 из Assets/map-editor-implementation-plan.txt»

Сделать:
  [ ] MapConfigEntry.instanceId (string)
  [ ] При загрузке конфига в рантайме: если instanceId пустой (старые ассеты
      в проекте) — сгенерировать GUID один раз? 
      Решение для НЕ-продакшена: Editor-утилита «Fix missing ids» ИЛИ
      генерация при первом открытии в Map Editor (этап 3).
      В этапе 1: поле + запись в сейв/чтение из сейва; пустой id в рантайме
      — LogWarning, клетка без прогресса или сгенерировать runtime-only
      (лучше: обязать заполнить через меню Assets до Play).
  [ ] MapCellSave: ключ instanceId; убрать зависимость прогресса от x,y
      как единственного ключа (x,y оставить полями)
  [ ] SaveSystem.CaptureMapCells / Load map: матч по instanceId
  [ ] MapSystem / миграции загрузки карты: применить сейв по id
  [ ] Краткая пометка в комментарии/architecture при наличии:
      «будущие миграции сейва — учитывать instanceId»

Не делать:
  - Editor Window
  - Миграцию старых player saves с coord-only

Проверка:
  - Play: сохранить/загрузить прогресс рейда на клетке
  - В ассете вручную проставить instanceId существующим entries

ЭТАП 3 — Map Editor Window: карта, dirty, Save, смена карты
════════════════════════════════════════════════════════════════════════
Запрос ИИ:
  «Реализуй этап 3 из Assets/map-editor-implementation-plan.txt»

Сделать:
  [ ] EditorWindow (меню IdleTower/Map Editor)
  [ ] Drop / ObjectField MapConfig — загрузка в рабочую копию
      (рекомендация: править через SerializedObject ассета;
      dirty = простой bool, true при любом изменении, без диффа ассета;
      явный Save → записать ассет + dirty = false)
  [ ] Кнопка Save с индикатором dirty (зелёная точка / аналог на иконке
      или рядом; видна только при dirty = true)
  [ ] При смене MapConfig / закрытии окна с dirty:
      диалог Да / Нет / Отмена (как выше)
  [ ] Превью iso: спрайты definition, позиция через helper этапа 2
  [ ] Виртуализация: создавать/обновлять визуал только в видимой области
      (пан/зум превью)
  [ ] Клик select по существующей клетке
  [ ] Пустые слоты в видимой области — опционально призраки (минимум:
      hit-test пустого coord под курсором для будущего paint)
  [ ] Генерация instanceId для entries без id при открытии карты в редакторе
      (и пометить dirty)

Не делать:
  - Paint / Move / Erase (этап 4)
  - Custom Inspector selection (этап 5) — на этом этапе select может
    только подсвечивать клетку в превью

Проверка:
  - Drop MapConfig, пан/зум, видна карта
  - Изменить что-то тестовое → Save → переоткрыть ассет
  - Dirty + смена карты → Да/Нет/Отмена

ЭТАП 4 — Paint, drag Definition, Erase, Move
════════════════════════════════════════════════════════════════════════
Запрос ИИ:
  «Реализуй этап 4 из Assets/map-editor-implementation-plan.txt»

Сделать:
  [ ] Drag MapCellDefinition из Project на coord (пусто → add, занято →
      заменить Cell, Site сбросить или спросить — по умолчанию: заменить
      только Cell, Site оставить; instanceId при replace на той же coord
      сохранить)
  [ ] Инструмент Paint (выбранный definition + клик/drag)
  [ ] Erase
  [ ] Move: pick cell → клик по целевому пустому coord; instanceId тот же;
      конфликт «занято» — запрет или swap (лучше запрет + сообщение)
  [ ] Все правки → dirty; только Save пишет на диск
  [ ] homeCoord: инструмент или кнопка «Set home to selection»

Проверка:
  - Поставить/удалить/сдвинуть клетку, Save, Play — позиция и прогресс
    (по id) ок после move

Критерий «можно давать всё за раз?»
----------------------------------
Технически можно одним запросом «реализуй этапы 1–5», но риск:
большого диффа, сложнее ревью и отладки сейва отдельно от Editor.
Рекомендация: минимум два запроса — (1) данные+сейв, (2) Editor 3–5;
идеально — по этапам 1 → 2 → 3 → 4 → 5.
)
