Ключевые решения:
  - Башня строго линейная (один столбец этажей снизу вверх), ветвления нет.
  - Функционал комнаты — не фиксирован: производство, свой UI, мини-игра и т.д.
  - Каждая комната ссылается на RoomBehavior (ScriptableObject) — плагин поведения.
  - Ядро знает только: построить, кликнуть, тикнуть, сохранить. Детали — в behavior.
  - Тик-цикл: частота тиков настраивается (плавность UI); баланс задаётся только в секундах.
  - Контентные Id стабильны (сейв); DisplayName — для игрока. Autofill Id / ResolveId нет.
  - Presenter в Idle Tower: связь Systems/фактов с выводом игроку (не только Canvas).

Цель: расширяемая архитектура, в которой геймплей, UI и данные разделены.
Новые комнаты, ресурсы и экраны добавляются через ScriptableObject и префабы
без правки ядра систем.

1. ПРИНЦИПЫ
================================================================================

1.1 Разделение слоёв (строгое, вариант 2)
    Data → Systems → Presenters → Views (и другие «выходы»: AudioSource, VFX…)

    Systems    — игровая логика; никаких ссылок на Canvas, Button, TMP, AudioSource.
    Presenters — слой связи Systems / GameEvents с выводом игроку:
                 UI, звуки, эффекты и т.п. Единственные, кто зовёт Systems по командам
                 игрока и кто подписывается на факты для презентации.
    Views      — пассивный вывод UI: SetText/Show/Hide, клики наружу; без бизнес-логики.
                 Для SFX/VFX «view» — AudioSource / ParticleSystem (управляет Presenter).

    В контексте Idle Tower слово Presenter НЕ ограничено Canvas:
    - UI: *Presenter + *Panel (пара на панель/экран)
    - звук: SfxPlayer (слушает факты → PlayOneShot)
    - позже: VFX-presenters по тому же принципу

    Правило для UI: на каждую панель/экран — пара *Panel (View) + *Presenter.
    Исключений для «простых» попапов нет — единообразие важнее экономии файлов.

1.2 Конфиг через ScriptableObject
    Комнаты, ресурсы, дерево разблокировок — ассеты в Project, не хардкод в коде.

1.3 События состояния — GameEvents (статический Event Bus)

    Два канала (не смешивать):
    - Команды (клики): View → Presenter → System.Method()
    - Факты (состояние): Raise* → Presenter → View / Audio / VFX

    Реализация: Scripts/Core/Events/GameEvents.cs
    - public static event + public static void Raise*(...) для каждого события
    - Целевое правило: Raise только из Systems после изменения данных
    - Факт кода: ResourceChanged / RoomBuilt / GameTick — из Systems;
      ProductionModeChanged / OperationModeUnlocked — из ProductionRoomBehavior
      (вынести в RoomBehaviorSystem или ослабить правило «только Systems»)
    - Подписываются Presenters (UI и SfxPlayer; UI часто пока попап открыт)

    События (актуально):
    ┌──────────────────────────────┬────────────────────────────┬────────────────────────────┐
    │ Событие                      │ Кто Raise                  │ Кто слушает                │
    ├──────────────────────────────┼────────────────────────────┼────────────────────────────┤
    │ ResourceChanged              │ ResourceSystem             │ ResourceListPresenter /    │
    │   (resource, newAmount)      │ Add / TrySpend / starting  │ UnitListPresenter          │
    │                              │                            │ (пока модалка открыта);    │
    │                              │                            │ RoomSelection /            │
    │                              │                            │ ProductionMode (пока open) │
    │ RoomBuilt                    │ BuildingSystem             │ TowerPresenter (UI);       │
    │   (roomIndex, room)          │ TryBuild успех             │ SfxPlayer → RoomBuilt      │
    │ GameTick                     │ GameTickSystem             │ TowerPresenter (overlay)   │
    │   (TickContext ctx)          │ каждый тик                 │                            │
    │ ProductionModeChanged        │ ProductionRoomBehavior     │ TowerPresenter →           │
    │   (roomIndex, ModeId)        │ TrySetMode                 │ ProductionModePresenter;   │
    │                              │                            │ SfxPlayer → ModeChanged    │
    │ OperationModeUnlocked        │ ProductionRoomBehavior     │ TowerPresenter →           │
    │   (roomIndex, ModeId)        │ TryUnlockMode (не OnBuilt) │ ProductionModePresenter;   │
    │                              │                            │ SfxPlayer → ModeUnlocked   │
    └──────────────────────────────┴────────────────────────────┴────────────────────────────┘

    Отложено (TODO в коде):
    - ScreenChanged(ScreenId id) — при 2+ экранах; Raise из ScreenManager.Show

    UI после действия игрока:
    - RoomSelectionPresenter: TryBuild → при успехе сам Hide()
    - Башня: RoomBuilt / GameTick; ресурсы в модалке: ResourceChanged (пока открыта)
    - Header «Ресурсы» / «Юниты» закрывают чужие модалки и открывают ResourceList / UnitList

    Расширение (фаза 6):
    1) IGameEvents — для unit-тестов без статики
    2) Больше SFX/VFX-Presenter’ов на другие факты GameEvents
    3) Новое событие — только если ≥2 подписчика или слабая связность критична
    4) Не публиковать команды (BuildRoom, OpenPanel) — только факты состояния
    5) Аналитика: отдельный AnalyticsListener на GameEvents
    6) Оптимизация (п. 9.1): batch ResourceChanged, debounce отрисовки

1.3.1 SFX-Presenter (масштабируемо)
    SfxPlayer — Presenter звука: GameEvents → SfxId → AudioClip.
    - SfxId enum — закрытый набор звуков
    - bindings[] в Inspector — свои клипы (опционально; иначе procedural тест)
    - Новый звук: SfxId + клип в bindings + одна строка подписки, если новый факт
    - OperationModeUnlocked не вызывается при стартовом unlock в OnRoomBuilt → SFX только при покупке режима
    SO-EventChannel не используем.

1.4 Единая точка входа
    GameBootstrap: ConfigValidator.ValidateOrThrow → GameServices → MainTowerPresenter.
    При ошибке конфига — LogError + exception, игра не стартует (enabled = false).

1.5 Состояние игры отделено от отображения
    TowerState / SaveData — чистые данные. TowerView только отражает состояние.

1.6 Расширяемость
    - Новая комната = RoomDefinition.asset + RoomBehavior.asset + запись в BuildingTree
    - Новый ресурс = ResourceDefinition.asset
    - Новый тип функционала = новый класс RoomBehavior (наследник) + SO-ассет
    - Новый экран = IScreen + регистрация в ScreenManager (комната может на него ссылаться)

1.7 Линейная башня (фиксировано, без ветвления)
    - Один столбец этажей снизу вверх; на этаже — одна комната.
    - Ровно один build-slot сверху; геометрического ветвления нет и не планируется.
    - «Ветвление» только в выборе комнаты из разблокированных в UI постройки.
    - RoomDefinition.Behavior — ОБЯЗАТЕЛЬНО, без null; для декора — PassiveRoomBehavior (когда понадобится).
    - Класс (ProductionRoomBehavior.cs) = логика; .asset = параметры в Inspector (см. п. 1.7.1).
    - Production: отдельный behavior asset на каждую комнату (Production_Lumbermill, Production_Quarry).
    - Смена режима: у каждого ModeId свой ElapsedSeconds; при TrySetMode меняется только ActiveModeId.
    - SerializeState / DeserializeState — внутри каждого behavior; в JSON — string Id режимов.

1.7.1 ScriptableObject и формат .asset
    - .cs  — код: алгоритмы, контракт IRoomBehavior, валидация.
    - .asset — YAML-файл Unity в Project; экземпляр SO с твоими настройками (modes, durations, icons).
    - Создание: ПКМ → Create → IdleTower → Production Room Behavior → Production_Lumbermill.asset
    - RoomDefinition ссылается на .asset через поле Behavior (перетаскивание в Inspector).
    - Зачем разделение: одна логика — много конфигов; баланс меняется без правки .cs; логика не смешана с полями Inspector.

1.7.2 Действия пользователя vs события состояния
    - Действия игрока (клик по комнате, слоту, кнопке): View → Presenter → прямой вызов System.
      Systems НЕ подписываются на клики через GameEvents.
    - События состояния: GameEvents → Presenters (см. п. 1.3)

1.8 Тик-цикл (Tick-based simulation)
    Частота тиков и баланс РАЗДЕЛЕНЫ:
    - TicksPerSecond (TPS) — настраиваемая «плавность» симуляции и UI; на баланс не влияет.
    - Все длительности в данных — в секундах (GameDuration), не в количестве тиков.

    Параметры (GameBalanceConfig):
    - int TicksPerSecond           — частота тиков (настраивается в asset при разработке); MVP: 10
    - float MaxCatchUpSeconds      — сколько секунд симуляции догоняем за один кадр (напр. 2.0)
    - int MaxTicksPerFrame         — вычисляется: TicksPerSecond * MaxCatchUpSeconds (10*2=20)

    Вычисляемые значения:
    - TickInterval = 1f / TicksPerSecond
    - При смене TPS пересчитывается только TickInterval; таймеры в секундах не сбрасываются.

    Алгоритм (GameBootstrap.Update):
    1) _accumulator += Time.deltaTime
    2) while (_accumulator >= TickInterval && ticksThisFrame < MaxTicksPerFrame):
         _accumulator -= TickInterval
         currentTick++
         TickContext: CurrentTick, TickDelta=TickInterval, TicksPerSecond, Services
         ITickable.OnTick в фиксированном порядке
         GameEvents.GameTick(ctx)
    3) Остаток _accumulator — для интерполяции UI (опционально)

    SimulationTimer (вместо счётчика тиков):
    - float elapsed в state поведения (у Production — ElapsedByMode[ActiveModeId])
    - каждый тик: elapsed += ctx.TickDelta
    - срабатывание: elapsed >= duration.TotalSeconds → действие, elapsed = 0
    - смена TPS 10→30: elapsed сохраняется → баланс в реальных секундах тот же

    GameDuration ([Serializable] struct):
    - int Minutes, int Seconds
    - float TotalSeconds => Minutes * 60f + Seconds
    - Пример: Minutes=0, Seconds=30 → 30 сек; Minutes=1, Seconds=30 → 90 сек
    - В Inspector задаёшь минуты и секунды; в коде везде TotalSeconds.

    currentTick (ulong) — счётчик тиков (отладка, save, аналитика); не использовать для баланса.

    Офлайн (позже):
    - elapsedWallSeconds = now - lastSaveTime
    - SimulateForSeconds(elapsedWallSeconds) — тики без лимита MaxTicksPerFrame, без UI

1.9 Именование (слои, типы, методы)

    Цель: по имени сразу видеть уровень абстракции и направление потока данных.

    Типы и суффиксы
    ┌──────────────────┬─────────────┬──────────────────────────┬─────────────────────────┐
    │ Суффикс / тип    │ Слой        │ Направление              │ Пример                  │
    ├──────────────────┼─────────────┼──────────────────────────┼─────────────────────────┤
    │ *Definition      │ Data        │ конфиг (SO), только чт.  │ RoomDefinition          │
    │ *State, Wallet   │ Data        │ runtime-состояние сессии │ TowerState, Wallet      │
    │ *Info            │ Systems     │ System → Presenter (DTO) │ OperationModeInfo       │
    │ *Display         │ UI          │ Presenter → View (DTO)   │ RoomOptionDisplay       │
    │ *Panel, *View    │ UI          │ только отображение       │ RoomSelectionPanel      │
    │ *Presenter       │ UI          │ мост View ↔ Systems      │ TowerPresenter          │
    │ *System          │ Systems     │ игровая логика           │ BuildingSystem          │
    └──────────────────┴─────────────┴──────────────────────────┴─────────────────────────┘

    *Info — read-model от System к Presenter: факты состояния (unlocked, active,
    canAfford, progress). Без UI-разметки (без текстов кнопок, ShowUnlockButton).
    *Display — DTO от Presenter к View: что нарисовать (label, кнопки, interactable).
    Presenter может передать *Info во View напрямую, если View уже принимает этот
    формат (пример: RoomStatusInfo → RoomView.SetStatus).

    Поток данных:
      System ──*Info──► Presenter ──*Display──► View
      View (клик) ──event──► Presenter ──Try*/Get*──► System
      System ──Raise──► GameEvents ──► Presenter ──Set*/Show──► View

    Методы Systems
    - Try*   — команда с проверкой (TryBuild, TrySpend, TrySetMode); bool или enum
    - Get*   — чтение без изменения (GetOperationModes, GetRoomStatusInfo)
    - On*    — lifecycle в ITickable / behavior (OnTick, OnRoomBuilt) — не путать с Presenter

    Методы Presenter
    - Handle*  — обработчик клика/события View (команда снизу): HandleRoomSelected,
                 HandleEmptyRoomClicked. Вызывает System или другой Presenter.
    - On*      — обработчик GameEvents (факт сверху): OnRoomBuilt, OnResourceChanged.
                 Читает System, обновляет View; не вызывает Try* без необходимости.
    - Refresh* — пересборка UI: чтение System → *Info/*Display → View (SetOptions, SetStatus)
    - Build*   — маппинг *Info → *Display внутри Presenter (BuildDisplay)
    - Open* / Close* / Show / Hide — управление видимостью попапа

    Методы View
    - Set*   — подставить данные в UI (SetOptions, SetStatus, SetResource)
    - Show / Hide — видимость панели
    - event Clicked, RoomSelected, … — сигнал «нажали» наружу; без вызова Systems

    GameEvents
    - Raise* — публикуют только Systems после изменения данных
    - Подписчики в Presenter именуют обработчики On* (не Handle*)

    События View vs GameEvents (не смешивать):
    - View.event + Presenter.Handle*  = команда игрока
    - GameEvents + Presenter.On*      = факт «состояние уже изменилось»

3. МОДЕЛЬ ДАННЫХ

3.1 ResourceDefinition (ScriptableObject)
    - ResourceId Id                  — typed; в ассете string, в API ResourceId
    - string DisplayName
    - Sprite Icon
    - bool IsUnit                    — юнит = тот же ресурс в Wallet; пока только
                                       отдельный список в OfflineResultPanel
    - int Strength                   — сила для набегов; в Inspector только при
                                       IsUnit (ResourceDefinitionEditor); при снятии
                                       галочки значение в ассете не стирается
    - ConfigValidator: Strength >= 0; при IsUnit — Strength >= 1

3.2 IRoomBehavior / RoomBehaviorBase (ScriptableObject)
    Контракт — ядро вызывает только эти методы; внутри — любая логика:

    - OnRoomBuilt(RoomBehaviorContext ctx)
    - OnRoomClicked(RoomBehaviorContext ctx) → RoomClickResult
        RoomClickResult: { RoomUiId? OpenUi } — behavior не открывает UI сам
    - Tick(TickContext ctx)
    - CreateDefaultState() → RoomBehaviorState
    - SerializeState / DeserializeState — формат свой у каждого behavior
    - GetRoomStatusInfo(ctx) → RoomStatusInfo (overlay на RoomView)

    RoomStatusInfo:
    - Sprite OutputIcon
    - string ModeLabel
    - ResourceCost[] InputPerCycle, OutputPerCycle
    - string CycleSummary
    - float Progress01, ElapsedSeconds, CycleTotalSeconds
    - bool WaitingForInput

    ProductionBehaviorState:
    - Dictionary<ModeId, float> ElapsedByMode
    - ModeId ActiveModeId
    - List<ModeId> UnlockedModeIds
    - bool IsPaused               — пауза этажа; Tick не крутит цикл; в сейве
    При TrySetMode: меняется только ActiveModeId; прогресс режимов независим.
    Tick / overlay: ElapsedByMode[ActiveModeId] (ActiveElapsedSeconds).
    ProductionModePanel: кнопка паузы (иконка pause / play).

    RoomUiId (enum):
    - None
    - ProductionMode
    - Shop                        — (позже, OpenUiRoomBehavior)

    Реализации:
    - ProductionRoomBehavior  — есть; отдельный .asset на комнату
    - OpenUiRoomBehavior / PassiveRoomBehavior — фаза 6

3.3 RoomDefinition (ScriptableObject)
    - RoomId Id                      — typed; runtime в TowerState — ссылка на SO
    - string DisplayName
    - Sprite Icon
    - GameObject Prefab
    - ResourceCost[] Cost
    - RoomBehaviorBase Behavior    — ОБЯЗАТЕЛЬНО
    - UnlockRule[] UnlockRules

3.4 OperationMode (OperationMode.cs — производство и крафт это одно)
    Термин: «операция» = цикл на этаже. Без входа = производство; с входом = крафт.

    - ModeId Id, string DisplayName, Icon
    - ResourceCost[] OutputPerCycle      — выдача за цикл (один или несколько ресурсов); пусто = нет выхода
    - GameDuration CycleDuration
    - ResourceCost[] InputPerCycle       — потребление за цикл; пусто = бесплатное производство
    - ResourceCost[] UnlockCost          — разовая оплата, чтобы режим стал доступен; пусто = открыт сразу
    - UnlockRule[] UnlockRules           — условия видимости (AND), как у комнат; опционально
    - bool UnlockedByDefault             — true для стартового режима (обычно modes[0])

    Цикл Tick (каждый вызов behavior.Tick) — одна операция для производства и крафта:

    - canAfford = InputPerCycle пуст → true; иначе CanAfford(InputPerCycle)
    - SimulationTimer.AdvanceCycle(elapsed, TickDelta, CycleDuration, canAfford) → bool cycleComplete
    - если !canAfford → ElapsedByMode[active] = 0 каждый тик (сброс прогресса крафта)
    - если cycleComplete → TrySpend(InputPerCycle) при непустом входе → Add(OutputPerCycle) → elapsed = 0
    - Когда ресурсов снова хватает — таймер крафта набирается с нуля

    Overlay: Progress01 = 0 пока canAfford == false (цикл сброшен).

    Разблокировка режима (отдельно от выбора активного):
    - TryUnlockMode(roomIndex, ModeId): UnlockRules ✓, ещё не unlocked, CanAfford(UnlockCost)
      → TrySpend(UnlockCost) → UnlockMode(ModeId) в state
    - TrySetMode(roomIndex, ModeId): mode уже unlocked → ActiveModeId; прогресс других режимов не меняется

    ProductionBehaviorState: см. п. 3.2 (ModeId, не modeIndex).

3.4.1 GameDuration
    - int Minutes, int Seconds
    - float TotalSeconds
    Используется везде, где в балансе есть время: производство, кулдауны, бафы.

3.5 UnlockRule (разблокировка для списка ПОСТРОЙКИ)
    Типы (enum UnlockRuleType):
    - AlwaysAvailable           — комната всегда в списке (если ещё не построена)
    - RequiresRoomBuilt         — на башне есть этаж с указанным RoomDefinition

    Логика нескольких правил на одной комнате: AND (все должны выполниться).
    RequiresResourceAmount — не используется.

    Уникальность: каждый RoomDefinition можно построить на башне только 1 раз.
    Повтор «той же» комнаты в late game — отдельный RoomDefinition в BuildingTreeConfig
    (копия с новым Id, своими UnlockRules, своим Cost); может требовать уже построенную
    «оригинальную» комнату через RequiresRoomBuilt.

    Пример дубликата:
    - room_lumbermill        — AlwaysAvailable, строится 1 раз
    - room_lumbermill_t2     — RequiresRoomBuilt(room_lumbermill) + другие rules,
                               отдельный asset, тот же prefab/behavior или свой

3.6 BuildingTreeConfig (ScriptableObject)
    - RoomDefinition[] AllRooms — полный реестр комнат для UnlockTreeSystem

    «Дерево» — логическое: связи через RequiresRoomBuilt между RoomDefinition.
    Геометрия башни линейная; ветвление — в выборе, какую из разблокированных комнат строить.

3.6.1 Разделение Unlock vs Cost
    - UnlockRules  — комната попадает в список UI (UnlockTreeSystem)
    - Cost         — хватает ли ресурсов (BuildingSystem.CanAfford)
    Заблокированные (rules не выполнены) — не показываются в UI.
    Разблокированные без ресурсов — показываются dim / «недоступно для постройки».

3.7 TowerState (runtime)
    - List<TowerRoom> Rooms
    TowerRoom:
    - RoomDefinition BuiltRoom      — null у пустой комнаты (слот строительства сверху)
    - RoomBehaviorState State       — произвольные данные поведения (режим, прогресс, флаги)
    - bool IsEmpty => BuiltRoom == null

    Инвариант: линейная башня, одна пустая комната сверху (EmptyRoomIndex).

3.8 ResourceWallet (runtime)
    - Dictionary<ResourceDefinition, int> (ключ = ссылка на SO; reference equality)
    - В сейве: ResourceId.Value (string); ApplyFromSave через каталог AllResources
    - CaptureForSave / ApplyFromSave — контракт для SaveSystem
    - Неизвестный / пустой Id при загрузке — exception
    - Backlog (Addressables): IEqualityComparer по ResourceId при дублях инстансов SO

Типизированные Id:
    - ResourceId, RoomId, ModeId — readonly struct над string
    - ScreenId, RoomUiId — enum (закрытый набор)
    - roomIndex: int — позиция слота башни, не entity-id
    - SerializeField / JsonUtility — string; публичный API — typed Id или SO
    - Id вручную в Inspector; дубликаты/пустота — ConfigValidator при старте
    - Смена Id ломает старые сейвы (нужна миграция)

3.9 RoomBehaviorContext (runtime, не сохраняется)
    - int RoomIndex
    - TowerRoom TowerRoom
    - TowerState Tower
    - GameServices Services
    Передаётся в каждый вызов behavior — доступ к ресурсам, UI, событиям без жёсткой связи.

4. СИСТЕМЫ И ОТВЕТСТВЕННОСТЬ

4.0 GameTickSystem
    Параметры — см. п. 1.8. Кратко:
    - TicksPerSecond — только в GameBalanceConfig (при разработке)
    - MaxTicksPerFrame = TicksPerSecond * MaxCatchUpSeconds (при TPS=10, CatchUp=2с → 20)
    - SimulateForSeconds(float) — офлайн, без MaxTicksPerFrame

    Порядок ITickable на тик (RegisterTickable):
    1) RoomBehaviorSystem
    2) (будущие: BuffSystem, QuestSystem…)
    3) (future ITickable…)

    ITickable vs Scripts/Systems/:
    - ITickable (Core) — только то, что вызывается каждый тик из GameTickSystem
    - ResourceSystem, BuildingSystem, UnlockTreeSystem — сервисы по запросу через
      GameServices; ITickable не реализуют
    - RoomBehaviorSystem — и сервис (GameServices.RoomBehaviors), и ITickable
    - Инициализация игры — GameServices.InitializeNewGame(), не ITickable

4.1 ResourceSystem
    CanAfford, TrySpend, Add; Raise ResourceChanged после изменения кошелька.
    null Resource в cost — exception (не silent skip).
    При нескольких ResourceCost — отдельный Raise на каждый ресурс (batch — п. 9.1).

4.2 UnlockTreeSystem
    - GetAvailableRooms(TowerState) → RoomDefinition[]
      1) Перебор BuildingTreeConfig.AllRooms
      2) Пропуск, если этот RoomDefinition уже построен (уникальность)
      3) Пропуск, если не все UnlockRules выполнены (AND)
      4) AlwaysAvailable: правило всегда true

    - IsAvailable / EvaluateRule — как раньше (RequiresRoomBuilt по ссылке SO)

4.3 BuildingSystem
    - TryBuild(roomIndex, RoomDefinition) → BuildResult
      … (без изменений по шагам) → RoomBehaviorSystem.OnRoomBuilt → GameEvents.RoomBuilt
    - CanAfford(room) → bool

4.4 RoomBehaviorSystem (ITickable + сервис)
    - OnTick / OnRoomClicked / OnRoomBuilt / GetRoomStatusInfo
    - Без knowledge о production-режимах

4.4.1 ProductionSystem
    - TryUnlockMode(roomIndex, ModeId) / TrySetMode(roomIndex, ModeId) → bool
      (делегирует в ProductionRoomBehavior; Raise mode-событий — внутри behavior)
    - GetOperationModes(roomIndex) → OperationModeInfo[]
    - Presenter: ProductionModePresenter → services.Production

4.5 ProductionRoomBehavior
    - OnRoomBuilt: unlock modes[0] (+ UnlockedByDefault); ActiveModeId = modes[0].Id
    - Tick: производство/крафт (п. 3.4); неизвестный ActiveModeId — exception
    - OnRoomClicked: всегда OpenUi = ProductionMode (даже при одном режиме)
    - SerializeState: ActiveModeId, UnlockedModeIds, ElapsedByMode (string Id в JSON)

4.5.1 ConfigValidator (при старте, не система тика)
    Проверяет Balance + BuildingTree: TPS, уникальные ResourceId/RoomId/ModeId,
    Behavior и UnlockRules у комнат, costs ∈ AllResources, CycleDuration > 0.
    Ошибка → InvalidOperationException из GameBootstrap.

4.6 OpenUiRoomBehavior — фаза 6
4.7 ScreenManager — без изменений по роли
4.8 SaveSystem
    - JSON в Application.persistentDataPath/idle_tower_save.json
    - Пишет: version, currentTick, tickAccumulator, savedUnixTimeUtc,
      resources[] (ResourceId+amount), rooms[] (RoomId + behaviorStateJson)
    - behaviorStateJson у Production: ActiveModeId, UnlockedModeIds, ElapsedByMode (все режимы)
    - Пустой слот башни не сериализуется — добавляется при Load
    - Автосейв: GameBootstrap каждые ~60с (unscaled) + pause / focus lost / quit / destroy
    - Старт: TryLoad (+ офлайн) → иначе InitializeNewGame

4.9 OfflineSimulationSystem
    - savedUnixTimeUtc — watermark UTC (unix +0), max(now, previous); откат часов не уменьшает
    - Catch-up: если now ≤ watermark → 0; иначе now − watermark → clamp 2ч → SimulateForSeconds
    - После догона watermark = now; GameEvents.Suppress на время симуляции
    - LastResult: real/simulated/wasCapped + дельты кошелька (до/после)
    - UI: OfflineResultPresenter после MainTower Init → TryShowFromLastCatchUp (если Applied)
    - Лимит позже от улучшений

4.10 OfflineResult (UI)
    - OfflineResultPanel + OfflineResultRowView + OfflineResultPresenter
    - Сводка: «Вас не было» / «Начислено за» (+ пометка лимита)
    - Два списка: обычные ресурсы (!IsUnit) и юниты (IsUnit); пустая секция скрывается
    - Показ только при Applied; Header «Ресурсы» закрывает попап

  - ProductionModePanel     + ProductionModePresenter
  - MainTowerScreen         + MainTowerPresenter
  - TowerView               + TowerPresenter

  Header «Ресурсы» → закрыть чужие + UnitList → ResourceList.Open (!IsUnit)
  Header «Юниты» → закрыть чужие + ResourceList → UnitList.Open (IsUnit)

UI поведений:

Структура: UI/Views, UI/Presenters, UI/Presenters/Rooms, UI/Screens

ScreenManager: один активный IScreen; Presenter экрана живёт вместе с View.

8. КОНФИГ MVP (баланс для первых ассетов)
================================================================================

Цель MVP: 4 ресурса, цепочка производство → крафт, разблокировка режимов за ресурсы,
переключение режимов, крафт с 1 и 2 входами, сброс цикла при нехватке.

Ресурсы (4 штуки — Create → IdleTower → Resource Definition):
  ┌────────────┬────────────┬──────────────────────────────────────────┐
  │ Id         │ DisplayName│ Откуда в MVP                             │
  ├────────────┼────────────┼──────────────────────────────────────────┤
  │ wood       │ Дерево     │ Лесопилка [0] Добыча                     │
  │ planks     │ Доски      │ Лесопилка [1] Распил (крафт из wood)       │
  │ stone      │ Камень     │ Карьер [0] Добыча                          │
  │ bricks     │ Кирпич     │ Карьер [1] Обжиг (крафт stone + planks)    │
  └────────────┴────────────┴──────────────────────────────────────────┘

Комнаты (постройка этажа):
  room_lumbermill
    UnlockRules: [AlwaysAvailable]
    Cost: пусто (или стартовый grant не нужен)
    Behavior → Production_Lumbermill.asset

  room_quarry
    UnlockRules: [RequiresRoomBuilt(room_lumbermill)]
    Cost: wood × 10
    Behavior → Production_Quarry.asset

Production_Lumbermill.asset — OperationMode[]:
  [0] «Добыча»
      UnlockedByDefault: true
      InputPerCycle: —
      OutputPerCycle: wood × 1
      CycleDuration: 3 сек

  [1] «Распил»
      UnlockedByDefault: false
      UnlockCost: wood × 5          ← разово открыть режим
      InputPerCycle: wood × 3       ← крафт; при нехватке — сброс цикла
      OutputPerCycle: planks × 1
      CycleDuration: 4 сек

Production_Quarry.asset — OperationMode[]:
  [0] «Добыча»
      UnlockedByDefault: true
      InputPerCycle: —
      OutputPerCycle: stone × 1
      CycleDuration: 3 сек

  [1] «Обжиг»
      UnlockedByDefault: false
      UnlockCost: stone × 8
      InputPerCycle: stone × 2, planks × 1   ← два входа; тест сброса если нет досок
      OutputPerCycle: bricks × 1
      CycleDuration: 5 сек

Тик-настройки (GameBalanceConfig):
  - TicksPerSecond = 10
  - MaxCatchUpSeconds = 2.0
  - MaxTicksPerFrame = 20  (вычисляется: 10 × 2)

Стартовые ресурсы (GameBalanceConfig):
  - wood: 0 (первая комната бесплатна; дерево копится с лесопилки)

Сценарий проверки в Play Mode:
  1. Построить лесопилку → режим [0], копится wood
  2. Накопить 5+ wood → клик по комнате → открыть «Распил» (UnlockCost)
  3. Переключить на [1] → при 3+ wood идёт крафт досок; при <3 — прогресс сброшен
  4. Построить карьер (10 wood) → stone
  5. Открыть «Обжиг», переключить → нужны stone + planks; без досок цикл сбрасывается
  6. Header → ResourceList показывает все 4 ресурса

BuildingTreeConfig.AllRooms: room_lumbermill, room_quarry

(фаза 6) room_shop, room_workshop — отдельные RoomDefinition + behaviors
