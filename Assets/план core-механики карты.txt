1. ЗАДАЧА (зафиксированная формулировка)
================================================================================

1.1 Экран
  - Новый экран: плоская карта из квадратов (сетка как Carcassonne).
  - Карта собирается ВРУЧНУЮ в Editor (не procedural).
  - Изначально дом Interactive; соседи (interactionRadius) — Interactive;
    дальше до visionRadius — VisibleOnly; остальное — Fog.
  - Дом: только возврат на экран башни.
  - Есть декоративные клетки без интеракции (только вид).

1.2 Клик
  - Интерактивная клетка → UI по типу behavior / фазы.
  - Декоративная / скрытая → клика нет (или клик игнорируется).

1.3 Набег (до захвата)
  - Требования конфига: мин. конкретные юниты + общая сила (добивка любыми
    юнитами в СОСТАВЕ, который выбрал игрок — без автоподбора).
  - Игрок в UI клетки задаёт количество каждого юнита → состав СОХРАНЯЕТСЯ
    на клетке (PlannedArmy). Этот же состав уходит в каждый следующий рейд.
  - Юниты СПИСЫВАЮТСЯ СРАЗУ И НАВСЕГДА при старте набега (ровно PlannedArmy).
  - Длительность в секундах; прогресс через GameTickSystem / ITickable
    (как ProductionRoom); офлайн catch-up тот же SimulateForSeconds.
  - Play / Pause:
      • Play всегда доступен (даже если юнитов в кошельке не хватает).
      • В режиме Play: как только в кошельке хватает на сохранённый состав
        и состав удовлетворяет требованиям — автостарт рейда; после
        завершения снова ждём накопления и шлём тот же состав.
      • Pause — только запрет НОВЫХ набегов; уже идущий не стопается.
      • Любое изменение состава → автоматически Pause, пока игрок снова
        не нажмёт Play.
  - На клетку одновременно только ОДИН набег.
  - Если Play у нескольких клеток в одном тике — порядок детерминированный
    по мировой сетке (y, затем x).
  - Лимит завершённых набегов (до захвата) → Captured → открытие соседей
    (reveal availability). RaidFarm при захвате стартует на Pause
    (игрок сам включает Play после проверки farm-цены).

1.4 После захвата
  - Dead / «завершена»: без геймплея; меняется текстура/вид.
  - RaidFarm: снова рейды с НОВЫМ конфигом; БЕЗ лимита числа рейдов.
  - Passive: доход по тику без отправки юнитов; свой UI (что / сколько / интервал).
  - Тип пост-режима: PostCaptureMode на RaidMapCellBehavior (см. R4);
    Inspector показывает поля выбранного режима.

1.5 One-shot лут
  - UI: содержимое + «Забрать».
  - При переходе клетки в Interactive (one-shot / захват / дорога)
    frontier пересчитывается СРАЗУ (интеракция + видимость + туман).
  - После клейма: клетка остаётся на карте, меняется текстурка (визуал
    «забрано»); не обязана становиться «дырой» в сетке.

1.6 Юнит
  - ResourceDefinition: IsUnit + Strength.
  - В Inspector Strength ВИДНО только при IsUnit=true; при снятии галочки
    значение Strength НЕ стирается, только скрывается (CustomPropertyDrawer /
    Editor GUI).

2. РЕШЕНИЯ ПО БЫВШИМ «ДЫРАМ» (зафиксировано игроком)
================================================================================

  [x] Юниты: списание навсегда при старте.
  [x] Strength: поле на ResourceDefinition; hide-if-not-unit в Editor.
  [x] Параллель на клетку: ровно 1 активный набег.
  [x] Несколько Play: сортировка клеток по координатам сетки, по порядку
      попытка автостарта в одном тике.
  [x] Состав армии: ручной выбор в UI, сохранение на клетке, повтор того же
      состава; Play всегда; смена состава → Pause; без TryBuildAutoArmy.
  [x] RaidFarm после захвата: без лимита рейдов.
  [x] Таймеры рейдов и пассива: тики + офлайн как production.
  [x] Карта: ручная авторская, не генерация.
  [x] Декоративная клетка без интеракции.
  [x] Глобальный «видимость/доступность соседей» ≠ логика захвата behavior.

Ещё актуально только как дизайн Editor (см. §8), не как дыра правил.


================================================================================
3. СТАТУСЫ: ГЛОБАЛЬНЫЕ VS BEHAVIOR
================================================================================

3.1 Глобальный слой карты — туман / видимость / интеракция

  Три состояния клетки (оба пересчёта НЕ в сейве; после Load — заново):

  Fog          — туман войны: клетки нет на карте / не рисуем содержимое
  VisibleOnly  — видна (спрайт/декор), клик НЕ работает, геймплея нет
  Interactive  — доступна к интеракции (если behavior это позволяет:
                 рейд, loot, дом→башня; декоратив по-прежнему без UI)

  Два радиуса в MapConfig (числа можно крутить в балансе):
  - interactionRadius — обычно 1: «соседи» по правилу 4/9
  - visionRadius — больше, напр. 2–3: «за несколько клеток дальше видно,
    но трогать нельзя»; всё, что дальше — Fog

  Кто «распахивает» (от них меряем оба радиуса) — как раньше:
    - дом (всегда);
    - захваченная рейдовая;
    - one-shot, как только сама стала Interactive (claim не нужен);
    - декоративная с галочкой revealsNeighbors (дорога да / река нет).

  Не распахивают (сами могут быть Interactive/Visible, но радиус от них
  дальше не тянут): декоратив без галочки; рейд до захвата.

  Как пересчитать:
    1) Собираем набор «распахивающих» (дом + захваченные + …), пока он
       стабилизируется: новые Interactive one-shot/дорога тоже входят.
    2) Interactive = клетки на расстоянии ≤ interactionRadius от этого набора
       (то же правило соседей, что 4 или 9).
    3) VisibleOnly = расстояние ≤ visionRadius, но не Interactive.
    4) Остальное = Fog.

  Пример (interaction=1, vision=2): дом открыл соседа-рейд A и one-shot B.
    A и B — Interactive. Соседи B дальше — Interactive (B распахивает).
    Клетки на 2 шага от распахивающих — только картинка. Дальше — туман.
    A до захвата «стенкой» не двигает frontier; после захвата A — и интеракция,
    и видимость сдвигаются.

  В рантайме после захвата / открытия one-shot — тот же пересчёт (или
  точечное обновление с тем же смыслом).

  Клики: только Interactive + behavior с действием. VisibleOnly — ignore.
  Fog — не кликаем / нет объекта.

3.2 Локальный слой (behavior + runtime state) — «что можно делать»
  Примеры (имена черновые):
  - Home: только UI «в башню»
  - Decorative: нет UI, клик ignore; опционально раскрывает соседей
    (галочка на behavior — см. ниже)
  - Raid: PreCapture (счётчик рейдов, play/pause, 0..1 active raid)
           → Captured → Dead | RaidFarm | Passive
  - OneShot: LootPending → LootClaimed (текстура другая; клик можно отключить
             или показать «пусто»)

  Итого: Fog/VisibleOnly/Interactive — MapSystem (пересчёт); геймплей — Behavior.


================================================================================
4. ONE-SHOT ПОСЛЕ CLAIM
================================================================================

После забора награды клетка ОСТАЁТСЯ на карте, меняется ТЕКСТУРА (claimed).
Соседи уже учтены при переходе в Interactive. Клик после claim — no-op или короткий UI
«уже забрано» (решить на этапе G).


================================================================================
5. МОДЕЛЬ СУЩНОСТЕЙ
================================================================================

5.1 SO / definitions
  MapConfig (ручная карта)
    - homeCoord
    - interactionRadius   // обычно 1
    - visionRadius        // > interaction; видимость без клика; дальше Fog
    - neighborMode        // 4 или 9 (или общий Neighbors)
    - entries[]: { Vector2Int coord, MapCellDefinition cell }

  MapCellDefinition
    - CellId, DisplayName, Sprite (или набор спрайтов по состоянию)
    - MapCellBehavior behavior

  MapCellBehavior (базовый SO)
    - HomeMapCellBehavior
    - DecorativeMapCellBehavior     — без интеракции
        revealsNeighbors: bool      // дорога=true, река=false; автор в SO/Editor
    - RaidMapCellBehavior
        preCapture: RaidConfig + maxCompletedRaids (>0)
        postCaptureMode: Dead | RaidFarm | Passive
        // Inspector: ниже только поля выбранного mode (CustomEditor)
        farmConfig: RaidConfig           // RaidFarm, без лимита рейдов
        passiveInterval + passiveRewards // Passive
        // Dead: смена спрайта / нет UI
    - OneShotLootMapCellBehavior
        loot: ResourceCost[]; sprites pending/claimed

  RaidConfig
    - requiredUnits[], requiredStrength, duration, rewards
    - для preCapture: рядом maxCompletedRaids
    - для farm (PostCaptureMode.RaidFarm): лимита нет

  ResourceDefinition
    - IsUnit, Strength (drawer: show Strength iff IsUnit; keep value)

5.2 Runtime
  MapState: coord → MapCellRuntime
    - mapPresence: Fog | VisibleOnly | Interactive
      // runtime-кэш; НЕ в сейве; RecomputeMapPresence()
    - behaviorState (JSON или поля): pause, completedRaids, activeRaid?,
      plannedArmy[], lootClaimed, passiveElapsed, phase…
      // в сейве — только behaviorState (+ то, что нельзя вывести)

5.3 Systems
  MapSystem : ITickable
    Tick: (1) прогресс активных рейдов/пассива
          (2) автостарт: Interactive+Play+состав ок+кошелёк хватает,
              sort (y,x), Spend(PlannedArmy)+Start
    TryTogglePause, TrySetPlannedArmyUnit, TryClaimLoot, RecomputeMapPresence…
  RaidArmyHelper — MeetsConfig, CanAfford, CalcStrength, TrySpend (permanent)

7. ЗАФИКСИРОВАННЫЕ ПРАВИЛА MVP (R*)
================================================================================

  R1. Юниты списываются навсегда при старте набега.
  R2. Максимум 1 активный набег на клетку.
  R3. Strength на ResourceDefinition; в Editor скрыт если !IsUnit, данные живут.
  R4. Пост-захват: enum PostCaptureMode на RaidMapCellBehavior;
      Inspector показывает только поля выбранного режима (Dead/RaidFarm/Passive).
  R5. RaidFarm: без лимита числа рейдов.
  R6. One-shot: при переходе в Interactive распахивает (claim не нужен);
      после claim — новая текстура.
  R7. Таймеры рейд/пассив — тики; офлайн — общий OfflineSimulation.
  R8. Автостарт при нескольких Play: sort клеток по (y, x) возрастанию
      (если понадобится другой ключ — одна правка в MapSystem).
  R9. Fog | VisibleOnly | Interactive — глобально у MapSystem, не в сейве;
      два радиуса (interaction / vision) от распахивающих; геймплей — behavior.
      VisibleOnly = только визуал; клик ignore. Fog = туман войны.
  R10. DecorativeMapCellBehavior — нет интеракции; галочка revealsNeighbors
      (распахивает при своей Interactive: дорога да / река нет).
  R11. Карта авторская; удобный Editor — цель §8.

8. АВТОРСКАЯ КАРТА В EDITOR — КАК УДОБНЕЕ
================================================================================

Цель UX:
  - клик по клетке → инспектор настроек (definition/behavior/спрайты);
  - кнопка «+» на ребре/у соседней пустой стороны → создать клетку;
  - без ручного набивания координат в огромном массиве.

Варианты (от простого к мощному):

  A) Только ScriptableObject MapConfig + кастомный Editor для MapConfig
     - List клеток с кнопками «добавить N/E/S/W от выбранной»
     - Превью сетки в EditorWindow (OnGUI / UIToolkit)
     - Плюс: не нужен Scene; минус: отдельное окно, не «как на сцене»

  B) EditorWindow «Map Painter» (рекомендация для вашего UX «+» и клик)
     - Рисует сетку из MapConfig
     - Select cell → SerializedObject выбранного MapCellDefinition
     - Кнопки + на гранях → Create asset / добавить entry в MapConfig
     - Без сторонних библиотек; UIToolkit или IMGUI
     - Плюс: ровно ваш сценарий; минус: пишем свой инструмент (~этап A2)

  C) Клетки как GameObject на сцене + custom MapCellAuthoring
     - Расстановка в Scene View, кнопка bake → MapConfig
     - Плюс: привычный Scene; минус: два представления (сцена vs runtime UI)

  D) Сторонние grid/tilemap-ассеты
     - Overlay на Tilemap обычно избыточен: у нас логические клетки с SO,
       не 2D-тайловый уровень. Библиотека редко даст «+»→SO behavior из коробки.

Рекомендация: **B — свой простой Map Editor Window** без внешних пакетов.
Этап A можно начать с ручного MapConfig (5 клеток); A2 — окно редактора.
Не блокировать геймплей ожиданием идеального Painter.
